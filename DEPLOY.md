# KOVA — Production Deployment Guide

Goal: make **https://kova-shopp.vercel.app** show the same 1,020 seeded
products, categories, and sellers that localhost does — plus working
checkout and emails — by deploying the NestJS API to Render and pointing
the Vercel frontend at it.

```
Browser ──► Vercel (Next.js frontend, kova/)
                │  NEXT_PUBLIC_API_URL
                ▼
            Render (NestJS API, kova-api/)
                │  DATABASE_URL
                ▼
            Postgres (same Prisma pooled DB used locally)
```

The frontend already falls back to `https://kova-api.onrender.com/api`
when running on a `*.vercel.app` hostname (`kova/lib/api.ts`), so a
Render service named **kova-api** needs zero frontend config. Set the
env var anyway to make it explicit.

---

## 1. Render — deploy the API (~10 minutes)

1. Go to <https://dashboard.render.com> → **New → Blueprint** → pick the
   repo (Blueprints live in `kova-api/render.yaml`).
2. When prompted, fill the `sync: false` values:
   - **`DATABASE_URL`** — copy the exact URL from `kova-api/.env`
     (the `pooled.db.prisma.io` connection string). Do **not** wrap it
     in quotes.
   - **`PAYSTACK_SECRET_KEY`** — same value as `kova-api/.env`.
   - **`RESEND_API_KEY`** — same value as `kova-api/.env`.
   - `JWT_SECRET` is auto-generated by the blueprint.
3. Deploy. Build ≈ 2–3 min. The start command runs
   `prisma migrate deploy` first, so all 6 migrations (including
   email-verification tables) apply against the shared DB automatically
   — idempotent, safe to re-run.

**Note on the shared DB:** Render connects to the same Postgres the
local dev machine uses. That means production traffic and local
seeding share data — convenient now, but plan a separate prod database
before real users sign up (see §5).

## 2. Vercel — point the frontend at the API

Project **Settings → Environment Variables** (Production + Preview):

| Variable | Value |
| --- | --- |
| `NEXT_PUBLIC_API_URL` | `https://kova-api.onrender.com/api` (or your real Render URL) |
| `NEXT_PUBLIC_SITE_URL` | `https://kova-shopp.vercel.app` |

Then **Deployments → Redeploy** (env changes only apply to new builds).
Free Render instances sleep after ~15 min idle; the first request then
takes ~50 s — that was the "warming up" behaviour, and it disappears
once the API answers.

## 3. Verify

```bash
curl https://kova-api.onrender.com/api/categories        # JSON list
curl "https://kova-api.onrender.com/api/products?limit=3" # 1,020 products in DB
```

Then in the browser: the Vercel site's homepage grid, shops, and
product pages should populate; add to cart → checkout should redirect
to Paystack and return to `/orders?reference=...`.

## 4. Email verification & password reset (Resend)

`FROM_EMAIL=onboarding@resend.dev` currently only delivers to the
**Resend account owner's inbox** (adeniyimarv@gmail.com). Password
reset works end-to-end for that address today; for everyone else:

1. Add your domain in Resend → Domains and add the DNS records.
2. Set `FROM_EMAIL="Kova <noreply@yourdomain.com>"` on Render.

Until then, tokens are still created for any address — only delivery
is restricted. Nothing else needs changing.

## 5. Hardening before real traffic

- **Separate prod DB** — create a dedicated Postgres (Neon/Supabase/
  Render) for production; run `prisma migrate deploy` against it and
  seed catalog data intentionally.
- **Paystack webhook** — add
  `https://kova-api.onrender.com/api/payments/webhook` in the Paystack
  dashboard so payments confirm even if the buyer closes the tab
  before redirecting back.
- **CORS** — `main.ts` already allows the Vercel domain; add more via
  `EXTRA_ORIGINS=a,b,c` on Render if needed.
- **Health check** — the blueprint uses `/api/categories` (public, DB
  backed) as Render's health check path.
