## 3. Dedicated seller shops (§1, §9, §10)

- Public shop pages live at `/store/<storeSlug>` (the existing route convention — not invented).
- Shop creation is **automatic** on seller activation: `POST /api/sellers/profile` assigns the SELLER role,
  generates a collision-safe slug (`romolas-place`, `-2`, `-3`…), and the shop is immediately public. Verified live
  earlier this session: `SellerOne Integration Store` → `/store/sellerone-integration-store` with zero manual steps.
- Shop pages show banner, logo, name, verified badge, location, description, real seller-rating summary + dimensions,
  product count, paginated catalogue (20/page, verified "page 2 of 11"), and Store JSON-LD.

## 4. Seller product CMS (§2, §11)

The full lifecycle is enforced server-side and verified live through the API: **create (DRAFT or publish:true) →
publish (validation: ≥3 images for physical, price/category/description rules) → unpublish → delete**, plus edits
(price, description, images, stock, category) with publish-rule re-validation on published items. Image uploads go
through the real `POST /api/uploads/image|images` endpoints (Cloudinary), max 5 files. The dashboard Listings tab
exposes publish/unpublish/edit/delete/share+QR per row, Orders tab handles fulfillment; a new **Shop settings** tab
edits shop name, description, location, payout email and uploads the logo — all persisted via `PATCH
/api/sellers/profile` (the DTO gained a validated `location` field for this).

## 7. Bugs found & fixed during this phase

1. **Tags DTO bug (blocked all product creation):** `@MaxLength(12, { each: false })` on the tags *array* validated
   the stringified array length — every create with tags failed. Fixed to `{ each: true }` with a 24-char per-tag cap.
2. **Dishonest featured-seller rating:** averaged all published products (unrated zeros dragged stores to "0.6★").
   Now averages **rated products only**, matching the dashboard's honest math (stores now show 3.6–4.2★).
3. **Store payload/`SellerStore` type drift:** aligned frontend type with the new paginated payload (`userId`,
   `ownerName`, `totalProducts`, `page(s)`, flat `products`) and kept the old `user.products` fallback.
4. **Build race:** a running server held the Prisma query-engine DLL, causing silent `EPERM` build failures —
   build-then-restart order fixed in the workflow.
